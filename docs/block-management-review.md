# ブロック管理機能：追加セルフレビュー

確認日：2026-10-28。Version 1.51.0を維持。既存サイトには接続せず、ローカルの自動テストと使い捨てWordPressで確認した。

## 発見した問題と最小限の修正

1. **起動直後の翻訳呼び出し**
   - OFF設定を読む際、管理用一覧のタイルギャラリー名を`__()`で翻訳していた。プラグイン読み込み直後にも実行されるため、翻訳ファイルがある環境では翻訳開始時期の警告につながり得る。
   - 起動前の翻訳呼び出しを追加テストで再現した。実WordPressで翻訳ファイルを用意して警告そのものを再現したわけではない。
   - 一覧作成は文字列の取得だけにし、翻訳は管理画面の描画時へ移した。27個別OFFで`init`前の翻訳呼び出しがないことを確認した。
2. **不正なnull値の解釈**
   - 管理フォーム形式の入力で`enabled`キーが明示的にnullのとき、未指定と同じ扱いになり、全OFFへ正規化されていた。
   - キーが存在するnullは不正値として全ONへ戻すよう修正。キー未指定・空配列は、正規の全OFF操作として維持した。
   - 通常のチェックボックス送信で生じる値ではなく、サニタイザーへの不正入力に対する修正。追加テストで確認した。

本体の変更は`includes/block-management.php`のみ。既存ブロックの登録名・属性・保存形式は変更していない。

## 重点7項目の結果

| 項目 | 確認した内容 | 結果・範囲 |
|---|---|---|
| 1. 全OFFでも管理できる | 実WordPressでダッシュボードとCNI Blocks設定画面がHTTP 200。切り替え23行と共通配色フォームを表示。全OFFから全ONへ保存して復帰 | 確認済み。OFFにしたブロックの編集UIは停止する仕様。見出し＋専用デザイン設定メニューもOFF時は停止し、ONで復帰する |
| 2. 保存・読み込み・権限・nonce | 実際の`options.php`へ保存し、次リクエストでDB値を読み込み。nonceなし・改ざん・別フォームnonceは403。編集者本人のセッション用nonceでも権限不足で403。未ログインの保存はログインへ302 | 確認済み。拒否後もDBの設定値は不変 |
| 3. 他ブロック・共通機能 | 27個別OFF、23操作単位それぞれの単独ON、共有ファイル利用の複合設定で登録・アセット依存を比較。全OFFでも共通配色保存ができ、ブロック設定を変更しないことを実WordPressで確認 | 確認済み。共通ファイルのコード／CSS文字列が残る既存制約は維持 |

| 6. 注意書き | OFF時の表示・編集への影響、データを削除しないこと、再ON、OFF中の編集・保存による復旧制限、親子連動、共有ファイル残存を明記 | 内容・フォーム出力を確認済み |

「全OFFでも設定画面が使える」は、管理切り替えと共通配色画面を指す。OFFのブロックを通常どおり編集できるという意味ではない。停止した機能固有の設定が必要な場合は、管理画面でONへ戻してから利用する。

- 23操作単位それぞれを単独ONにして、ほかがOFFでも依存が成立することを追加確認。
- 4親子単位について親側・子側の一方だけを指定したOFF値、親チェックだけを送るON値を検査。
- 全OFFから表示した実フォームの「すべてON」→サニタイズ→次リクエストで27登録へ復帰することを追加確認。
- 全OFFでも設定グループ・管理メニュー・2つのフォームが残ることを明示的に検査。
- 起動前の翻訳呼び出し、null入力の回帰テストを追加。

### 実WordPress統合テスト

実行：`node tests/block-management-wordpress.cjs`。

- WordPress公式Playground CLIをnpmキャッシュから使用。リポジトリへ依存パッケージやビルド設定は追加していない。
- WordPress 6.8.3、PHP 8.3、SQLite、一時的な標準テーマ環境。
- プラグインの必要ファイルをOSの一時領域へコピーしてマウント。既存サイト・既存DBへ接続していない。
- 管理者、編集者、検証用ページ・メタを一時サイトに作成。
- 管理者ログイン→漫画OFF→全OFF→共通配色保存→全ONを、実際の管理フォームと`options.php`で実施。
- 画面の再読み込み、DB設定値、ブロック登録数、本文、検証用メタ、公開用描画結果を比較。
- nonceなし・改ざん・別フォームnonceをPOSTし、403とDB不変を検査。
- 編集者での画面アクセス・保存拒否を検査。編集者本人のセッションで生成した正しいnonceを使っても保存は403。
- 未ログインの保存要求はログイン画面への302誘導となり、DB値が変わらないことを検査。
- Gutenbergを全ON／全OFF／再ONの各状態で開き、クライアントの登録数と保存済み漫画ブロックの認識状態を検査。投稿は保存しない。
- 終了時はブラウザーと一時サーバーを停止し、検証用プラグインコピーを削除する。配布ZIPを生成しない。

サーバー側は27→26→0→27、Gutenberg側は27→0→27を確認。本文と検証用メタは一致し、漫画ブロックの再ON後のHTMLも初期状態と一致した。共通配色`#123456`はブロック設定の保存後も維持された。

最終構文検査：PHPの修正2ファイル、JS/CJS全47ファイル、JSONのパース、`git diff --check`が通過。ブロック管理の拡張テストと実WordPress統合テストも通過した。今回の本体修正は管理PHPのみのため、初回に通過した既存11本の機能テストは今回は再実行していない。

## 残る制約・未検証

- 実サイトのテーマ・追加プラグイン・ページキャッシュとの組み合わせ、マルチサイト、WordPress 6.3や他PHPバージョンは未検証。
- 全27種類それぞれの内容をGutenbergで編集・保存する総当たり確認は未実施。実Gutenbergで復旧を確認した保存済み内容は漫画＋標準段落。
- OFF中に投稿を編集・保存したケースの完全復旧は保証しない。
- OFFは保存済みHTMLを消す機能ではない。静的HTMLや他のONブロックが使う共有CSSによって、既存表示の一部が残ることがある。
- 登録対象のJS/CSSサイズ比較は前報告のまま。実サイトの圧縮後転送量・表示速度は未測定。
- 管理設定は次のリクエストから反映する。すでに開いているエディターやキャッシュ済みページは再読み込みが必要。
- Version変更・コミット・プッシュ・タグ・配布ZIP生成／更新・公開は行っていない。
