# ブロック別ON／OFF管理：実装・検証報告

確認日：2026-10-28。プラグインVersionは1.51.0のまま。

追記：本書は初回実装時点の記録。追加セルフレビューでの修正と、一時WordPressによるHTTP・DB・Gutenberg検証の最新結果は [block-management-review.md](block-management-review.md) を参照。以下の「実WordPress未検証」は初回検証時点の状態を記録している。

## 1. 実装した機能と管理画面

既存の「設定 → CNI Blocks」画面で、背景生成＋の共通配色フォームの下に「使用するブロック」を追加した。

- 全27ブロックを管理する。内部の子ブロックを含む4組は、親子が同時に切り替わる23行の操作単位とした。
- 個別ON／OFF、一括すべてON／OFF、現在の状態・件数、未保存の状態、保存を実装。
- 「すべてOFF」は確認ダイアログを表示する。一括操作だけでは保存しない。
- ページ表示は`manage_options`で制限する。保存はSettings APIの`options.php`を使い、標準の権限・nonce確認に委ねる。フォームは専用の設定グループを使う。
- 入力は既知のブロック名とスキーマだけを受け入れる。壊れた設定は全ON、未知の名前は無視する。
- 保存先は新設の`cni_blocks_block_management`オプションだけ。形式は`{"version":1,"disabled":["cni-blocks/page-flip"]}`。指定されていないブロックはON。
- 設定が存在しない既存サイト・新規サイトは全ON。将来追加されるブロックも、明示的なOFF指定がなければON。
- OFFで既存表示・編集が変わり得ること、データは削除しないこと、OFF中の編集・保存後は完全復旧を保証できないことを画面内に明記した。

既存の共通配色フォームと管理画面スラッグは維持している。見出し＋の独自デザイン設定は、見出し＋がONの間のみ従来どおり登録する。OFF時も保存済みの独自デザイン・プリセットは削除しない。

## 3. 構造調査と停止される処理

既存の登録は`cni_blocks.php`の1関数へ集約されていた。ブロックごとのJS・CSSはほぼ分離済みで、バンドラーやnpmビルドは使っていない。保存形式・ブロック配置・ディレクトリ全体の再編は不要だった。

- PHPのブロック登録を条件付きにした。OFFのブロックはWordPressへ登録しない。
- 専用スクリプト・スタイルの登録を停止する。登録されないため、WordPressの一括ブロックアセット読み込みからも外れる。
- 投稿リスト、選択投稿リスト、パンくず、カスタムフィールド、地図、サークル画像、Image Hotspot、画像テキストレイヤー、漫画ビューアーの専用`render.php`は、OFF時に読み込まない。
- 選択投稿リストの検索RESTルート、見出しのプリセットRESTルート・独自CSS出力・専用設定画面は、対象がOFFなら登録しない。
- 投稿リストの投稿タイプ・分類・ターム取得と、見出し／背景生成のエディター用設定データ生成も、対象がOFFなら行わない。
- Outer+がOFFならヒーロー背景のプリロードフックを登録しない。
- ギャラリーの共通編集JSは、有効な方だけをJavaScript側へ登録する。
- 共通公開JSが残る場合も、OFFのギャラリーや見出し／画像テキストレイヤーの初期化をスキップする。

投稿リストの分類取得・バッジ描画ヘルパー2個だけを新しい共通PHPへ移した。これにより、投稿リスト+をOFFにしても選択投稿リスト+の描画に必要なヘルパーは使用できる。既存の関数名と処理内容は維持した。

## 4. OFFでも残る処理と理由

| 残るもの | 条件・理由 |
|---|---|
| ギャラリー共通`index.js`／`view.js`／`style.css` | 2種の片方がONなら残る。OFF側の登録・初期化は止めるが、同一ファイル内のコード・CSS文字列は分割していない。両方OFFなら登録しない。 |
| `blocks/shared/text-designs.js` | 見出し＋または画像テキストレイヤーがONなら必要。 |
| 見出し用CSS・公開JS | 画像テキストレイヤーも文字デザインとフォント処理を利用するため、どちらかONなら必要。OFF側の公開JS初期化は止める。 |
| 投稿リスト用CSS・共通PHPヘルパー | 選択投稿リストも利用する。どちらかONなら必要。専用描画PHPや専用エディターJSは別に停止する。 |
| 管理画面・オプション取得・メタデータ一覧・登録可否の判定 | 再ON操作と新ブロックの初期ON、依存関係の判定に必要。全ON時は管理一覧の追加読み込みを避ける経路を設けた。 |
| 登録関数内のパス生成・一部の`filemtime()`など | 既存の登録関数を維持したため、OFFでも登録可否を判断する前の軽微な準備処理は残る。 |
| メインPHPのユーティリティ関数定義・共通配色の設定登録・更新機能 | プラグイン共通機能と設定復旧のために維持する。専用描画PHPの停止とは分けている。 |
| 保存済みHTML | 投稿本文を変更しないため、OFFでも静的HTMLが残って表示される場合がある。OFFはコンテンツの非表示機能ではない。共通CSSが残る組み合わせでは、そのHTMLに共通CSSが適用される場合もある。 |

片側だけONの共通ファイルからOFF側のコード文字列・CSSまで除去するには、ギャラリーや文字デザインのファイル分割が必要になる。今回は既存依存と全ON時の互換性を維持し、大規模な共通アセットの再編は行っていない。

## 5. JS・CSSの削減効果

以下はローカルPHP検証で登録された、プラグイン内JS・CSSのユニークなファイルの合計。圧縮前のディスク上の実サイズであり、WordPress本体のライブラリ・管理画面専用の新JS・インライン設定は含まない。

| 条件 | JS | CSS | 合計・差分 |
|---|---:|---:|---:|
| 全ON | 33本 | 22本 | 1,143,230バイト |
| 漫画ビューアーのみOFF | 31本 | 21本 | 45,860バイト削減 |
| 全OFF | 0本 | 0本 | 上記1,143,230バイトが登録対象から外れる |

漫画ビューアーの内訳：編集JS 19,958バイト、公開JS 13,004バイト、CSS 12,898バイト。

これは編集用・公開用を合わせた登録対象の比較であり、1ページで常に全量が転送されていたという意味ではない。実サイトのHTTPリクエスト数、gzip/Brotli圧縮後の転送量、ページキャッシュ利用時の変化、表示速度は未測定。

## 6. OFF→ONの復旧検証

PHP API検証用ハーネスで、リクエストごとに実際のプラグインPHPを新しいプロセスへ読み込ませて確認した。

- 初期状態→全OFF→全ONで、27ブロックの登録・属性・描画コールバックが復帰した。
- 保存済み相当の漫画ビューアー属性から生成するHTMLが、初期状態と再ON後で一致した。
- 検証用の保存済みブロック文字列と、既存のオプション値はON／OFFで変化しなかった。
- 管理画面の実フォームをブラウザーで操作し、フォーム値をサニタイズして次リクエストへ渡すことで、個別OFF・全OFF・全ONの保存後相当の再表示を確認した。
- 特別な移行処理は実装していない。

実データベース上の投稿・メタデータを使うWordPressの保存・復旧操作は未検証。OFF中にGutenbergで対象ページを編集・保存するケースの完全復旧は、仕様どおり保証しない。

## 7. 後方互換性

- ブロック名・スラッグ・属性・保存形式を変更していない。
- 全ONの登録・メタデータ・アセット・設定データ・RESTルート・サンプル描画結果を、今回の作業前に保存したPHPソースと比較し一致した。
- 共通ギャラリーの属性と保存関数も変更前と一致した。
- 旧背景生成＋の既存の挿入候補非表示仕様を維持する。旧版をONにしても新規候補へ増やす変更はしない。
- 投稿本文・メタデータ・既存設定を書き換える移行・削除・変換処理は追加していない。
- 元から作業中だったGrid+、背景生成＋、固定表示＋、Outer+の変更は保持した。

## 9. 実施した検証・未検証事項

確認済み：

- PHP構文検査、JS/CJS構文検査、JSONパース、差分の空白検査。
- 全ONの作業前との比較、27個別OFF、共通ファイルを利用する複合設定、全OFF／再ON。
- 専用PHP未読み込み、描画関数・REST・プリロード・専用設定データ生成の停止。
- 有効ブロックに必要なアセットと依存先が過不足なく登録されること。
- 不正な設定値、未知の名前、サニタイザーの二重実行、一括フォーム値、親子の連動。
- 管理権限を持たないユーザーへのフォーム非表示、Settings APIの設定グループ・nonce出力呼び出し。
- 実フォームの一括OFF確認／キャンセル、個別チェック、状態件数、キーボード操作、再表示、PC／モバイルでのレイアウト。
- 共通ギャラリー編集JSの登録抑制、共通公開JSのOFF側初期化抑制。
- 既存の背景生成＋、Grid+、見出し変換、自由配置画像、固定表示＋、Outer+フレームの11検証スクリプトも通過。

検証の範囲：PHP側はWordPress APIを検証用関数に置き換えた契約テスト。ブラウザーは、そのPHPが出力したフォームと実際の管理JSを使った独立した画面。実WordPressや実サイトへは変更を反映していない。

未検証：実WordPressへのログイン・`options.php`経由のDB保存、nonce不正時／権限不足時のHTTP応答、全27ブロックそれぞれのGutenberg編集・保存、マルチサイト、他プラグインとの併用、実サイトのHTTP転送量・速度。

実機確認手順：

1. 検証サイトで全ONのまま既存ページの表示・編集と、既存の共通配色設定の保存を確認する。
2. 「設定 → CNI Blocks → 使用するブロック」で漫画ビューアーをOFFにして保存する。
3. エディターを再読み込みし、挿入候補から消えること、専用JS／CSSが開発者ツールのNetworkから外れることを確認する。
4. 既存漫画ページはOFF中に保存せず、再ONして認識・表示が戻ることを確認する。
5. Grid+などの親子連動と、投稿リストOFF／選択投稿リストON、見出しOFF／画像テキストレイヤーONを確認する。
6. ページキャッシュ・アセット結合を使っている場合はキャッシュを更新して再確認する。
7. 管理権限のないアカウント・無効nonceで保存できないことを確認する。

## 10. 残る制約・今後の追加方法

- 機能単位での停止であり、保存済みHTMLの削除・強制非表示は行わない。
- 4組の親子ブロックは一体で停止する。共有アセットは他の利用側がONなら残る。
- 実WordPressでの保存・復旧とネットワーク確認は上記手順で追加確認が必要。
- 将来の`blocks/*/block.json`は管理一覧へ自動で取り込む。ブロック登録には`cni_blocks_register_block_type()`、専用アセット登録には`cni_blocks_register_script()`／`cni_blocks_register_style()`を使用する。専用PHPは`cni_blocks_block_enabled()`で条件付きにする。
- 新しい共有ファイルを追加するときは`cni_blocks_asset_owners()`へ利用側を列挙する。未知の汎用ハンドルは、安全のため停止しない設計。
- インラインでブロックを追加する場合は、タイルギャラリーと同様に管理一覧にも記載する必要がある。
- PHPの可否判定は1リクエスト内で固定する。設定保存後の次のリクエストで反映される。
- 今回はVersion変更、Git操作、タグ作成、ZIP生成・更新、公開を行っていない。既存ZIPには今回の機能はまだ含まれない。

参照：WordPress公式 [Settings API](https://developer.wordpress.org/plugins/settings/using-settings-api/)、[settings_fields（nonce・action・option_pageの出力）](https://developer.wordpress.org/reference/functions/settings_fields/)。
